## Bukti status sebagian di plaesy

Setiap baris `sebagian` mengacu ke modul plaesy yang mengimplementasikan sebagian perilaku itu dan punya tes. Pemeriksaan memakai pencarian kata kunci pada `crates/`, lalu pembacaan modul dan berkas tesnya. Kecocokan kata kunci yang hanya kebetulan tidak dihitung. Status `sebagian` hanya mencakup bagian yang disebut di baris; sisa perilaku OpenBot pada baris yang sama tidak diklaim.

- OBT-036 (antrean FIFO), OBT-037 (pesan tetap ada setelah restart), OBT-039 (pesan agen ke agen), dan OBT-040 (kunci retry): `crates/plaesy/adapter/relay/src/relay.rs` (`send`, `inbox` dengan `ORDER BY created_at,id`, `claim_next`, ack berbasis token). Tes di `crates/plaesy/adapter/relay/src/relay_test.rs`: `idempotent_send_and_explicit_ack_preserve_queue_semantics`, `concurrent_idempotent_retries_create_only_one_message`, dan `pending_message_survives_store_reopen`. OBT-038 (jeda, lanjut, batalkan antrean) tetap `belum`: relay tidak punya operasi jeda atau lanjut, dan tidak ada reaksi atau transfer berkas.
- OBT-044 (pembatalan): `crates/plaesy/domain/workflow/src/task_run/mod.rs` (`Event::Cancel`, status `Cancelled`); tes `crates/plaesy/domain/workflow/src/task_run/task_run_test.rs`. Pembatalan plaesy berlaku pada run tugas, bukan pada pesan yang masih diantrekan.
- OBT-045 (status run): status terminal `Succeeded`, `Failed`, `TimedOut`, `Cancelled` di `task_run/mod.rs`; tes `task_run_terminal_state_refuses_further_events` dan `task_run_replay_of_completed_run_matches_live_state`. Perilaku restart berbeda: plaesy menjadwalkan ulang run yang berjalan (`task_run_restart_while_running_is_requeued_within_policy`), sedangkan OpenBot menandainya terinterupsi. Perbedaan itu dicatat di OBT-046, yang tetap `belum`.
- OBT-095 (endpoint OpenAI-compatible): `crates/plaesy/adapter/model-openai-tools/src/openai_test.rs` (`openai_tool_call_arguments_are_parsed_and_result_sent_with_tool`, `openai_api_key_is_sent_as_bearer_from_env_var`) dan `crates/plaesy/support/loop/src/loop_run/step_adapter_test.rs` (`an_openai_step_without_an_endpoint_is_refused`). Kunci API dibaca dari variabel lingkungan. Tidak ada daftar endpoint per agen dan tidak ada antarmuka.
- OBT-097 (Ollama dengan tool call): `crates/plaesy/adapter/model-ollama/src/ollama_test.rs` (`ollama_tool_call_is_executed_and_result_sent_back_to_model`, `ollama_endless_tool_loop_stops_at_the_round_limit`, `ollama_unreachable_endpoint_is_an_error`). Deteksi otomatis server Ollama dan LM Studio (OBT-096) tidak ada di plaesy.
- OBT-104 (`remember`): `crates/plaesy/adapter/memory/src/notes/notes_test.rs` (`remember_refuses_link_out_of_root`). Memori plaesy adalah catatan Markdown di vault, bukan memori per agen; yang dihitung hanya fungsi tulis catatan.
- OBT-105 (`search_memories`): `crates/plaesy/adapter/memory/src/mcp/mcp_test.rs` (`search_tool_returns_cited_text_and_structured_hits`, `mcp_search_result_conforms_to_output_schema`). Hasil plaesy memuat kutipan jalur dan baris; belum ada bukti bahwa OpenBot memakai format yang sama.

Kandidat yang dibaca tetapi tidak dihitung sebagai `sebagian`:

- Interval rutin: `crates/plaesy/adapter/memory/src/schedule/mod.rs` (`parse_every`, `is_due`). Itu hanya primitif interval untuk pekerjaan memori; tidak ada runner rutin, webhook, atau kalender.
- Persetujuan: `crates/plaesy/domain/workflow/src/policy/approvals.rs` menyimpan persetujuan rahasia, bukan persetujuan tindakan agen seperti pada Local scripts.
- Akses per prinsipal: `crates/plaesy/domain/identity/src/authz/mod.rs` (`check`; tes `authz_test.rs`) memberi dan mencabut grant, tetapi tidak punya tingkat none, view, atau chat. Baris akses per agen tetap `belum`.
- Klaim tugas: `crates/plaesy/support/tasks/src/tasks/claim.rs` mengatur klaim tugas berbasis folder, bukan konsep antrean OpenBot.
