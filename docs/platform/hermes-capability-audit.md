## Source review follow-up (pinned source; no tests run)

A focused source inspection was performed at the pinned SHA above. These are source/test-contract observations, not test-executed behavior:

- `agent/runtime_session_store.py:1-4` explicitly says the worker facade is not a complete `SessionDB` substitute and existing cron/child/compute consumers are not switched before inventory coverage.
- `tests/agent/test_runtime_session_store_surface_parity.py:1-4,22-46` defines a source-inspection test contract: every `SessionDB` method called by agent core must exist on `RuntimeSessionStore` with compatible keywords; `49-69` compares selected tail reads against owner `SessionDB`. Test file inspected only; not run.
- `agent/runtime_session_lifecycle.py:1-4,83-93` distinguishes closing local store from ending session and settling execution, including deferred work. Source reviewed; no claim that all recovery cases are covered.
- `tests/hermes_cli/test_skills_install_trust_provenance.py:1-7,40-59,75-93,148-177` contains assertions that marketplace/publisher-controlled identifiers must not elevate trust and dangerous skills remain blocked, including index/upstream-pointer cases. Test file inspected only; not run.
- `agent/memory_provider.py:1-5,84-100` documents one-provider lifecycle and profile isolation requirements. Source reviewed; no runtime verification.
- `agent/checkpoints/manager.py:1-48` documents shared shadow-store snapshots, pruning, and total-size cap. `tests/agent/checkpoints/test_checkpoint_size_cap.py:31-74`, `test_checkpoint_store_ownership.py:1-54`, and `test_checkpoint_store_self_exclusion.py:1-94` assert size/retention, writer ownership, and store self-exclusion contracts; inspected only, not executed.

Disposition: extend existing `critical_feature-implement-durable-task-run-lifecycle-and-recovery` acceptance with worker-store surface parity and separation of session close/execution/deferred-work settlement. Extend the existing knowledge/provenance task with adapter-origin trust and profile isolation requirements. Checkpoint lifecycle could fit `high_feature-enforce-isolated-concurrent-agent-changes` only if that task owns snapshot/restore; otherwise map to `high_chore-verify-install-backup-restore-and-rollback-lifecycle`. No distinct new implementation task is justified from this bounded inspection alone. Additional test/source files found by filename search were not inspected and remain UNKNOWN.
